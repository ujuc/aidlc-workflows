# 코드 생성 - 상세 단계

## 개요
이 스테이지는 두 가지 통합 파트를 통해 각 작업 단위에 대한 코드를 생성합니다:
- **파트 1 - 계획**: 명시적 단계가 포함된 상세 코드 생성 계획 작성
- **파트 2 - 생성**: 승인된 계획을 실행하여 코드, 테스트 및 산출물 생성

## 전제 조건
- 해당 유닛에 대한 유닛 설계 생성이 완료되어야 함
- NFR 구현 (실행된 경우) 해당 유닛에 대해 완료되어야 함
- 모든 유닛 설계 산출물이 사용 가능해야 함
- 유닛이 코드 생성 준비가 되어 있어야 함

---

# 파트 1: 계획

## 단계 1: 유닛 컨텍스트 분석
- [ ] 유닛 설계 생성에서 유닛 설계 산출물 읽기
- [ ] 할당된 스토리를 이해하기 위해 유닛 스토리 맵 읽기
- [ ] 유닛 의존성 및 인터페이스 식별
- [ ] 유닛이 코드 생성 준비가 되었는지 검증

## 단계 2: 상세 유닛 코드 생성 계획 작성
- [ ] 유닛 생성을 위한 명시적 단계 작성:
  - 비즈니스 로직 생성
  - 비즈니스 로직 단위 테스트
  - 비즈니스 로직 요약
  - API 레이어 생성
  - API 레이어 단위 테스트
  - API 레이어 요약
  - 리포지토리 레이어 생성
  - 리포지토리 레이어 단위 테스트
  - 리포지토리 레이어 요약
  - 데이터베이스 마이그레이션 스크립트 생성 (데이터 모델이 있는 경우)
  - 문서 생성 (API 문서, README 업데이트)
  - 배포 산출물 생성
- [ ] 각 단계에 순차적 번호 부여
- [ ] 이 유닛에 대한 스토리 매핑 참조 포함
- [ ] 각 단계에 체크박스 [ ] 추가

## 단계 3: 유닛 생성 컨텍스트 포함
- [ ] 이 유닛에 대해 포함할 내용:
  - 이 유닛이 구현하는 스토리
  - 다른 유닛/서비스에 대한 의존성
  - 예상 인터페이스 및 계약
  - 이 유닛이 소유한 데이터베이스 엔티티
  - 서비스 경계 및 책임

## 단계 4: 유닛 계획 문서 생성
- [ ] 전체 계획을 `aidlc-docs/construction/plans/{unit-name}-code-generation-plan.md`로 저장
- [ ] 단계 번호 포함 (단계 1, 단계 2 등)
- [ ] 유닛 컨텍스트 및 의존성 포함
- [ ] 스토리 추적성 포함
- [ ] 계획이 단계별로 실행 가능한지 확인
- [ ] 이 계획이 코드 생성의 단일 진실 소스임을 강조

## 단계 5: 유닛 계획 요약
- [ ] 사용자에게 유닛 코드 생성 계획 요약 제공
- [ ] 유닛 생성 접근 방식 강조
- [ ] 단계 순서 및 스토리 커버리지 설명
- [ ] 총 단계 수 및 예상 범위 기록

## 단계 6: 승인 프롬프트 기록
- [ ] 승인을 요청하기 전에 `aidlc-docs/audit.md`에 타임스탬프와 함께 프롬프트 기록
- [ ] 전체 유닛 코드 생성 계획에 대한 참조 포함
- [ ] ISO 8601 타임스탬프 형식 사용

## 단계 7: 명시적 승인 대기
- [ ] 사용자가 유닛 코드 생성 계획을 명시적으로 승인할 때까지 진행하지 않음
- [ ] 승인은 전체 계획과 생성 순서를 포함해야 함
- [ ] 사용자가 변경을 요청하면 계획을 업데이트하고 승인 프로세스 반복

## 단계 8: 승인 응답 기록
- [ ] `aidlc-docs/audit.md`에 타임스탬프와 함께 사용자의 승인 응답 기록
- [ ] 정확한 사용자 응답 텍스트 포함
- [ ] 승인 상태를 명확히 표시

## 단계 9: 진행 상황 업데이트
- [ ] `aidlc-state.md`에서 코드 계획 완료 표시
- [ ] "현재 상태" 섹션 업데이트
- [ ] 코드 생성으로 전환 준비

# 파트 2: 생성

## 단계 10: 유닛 코드 생성 계획 로드
- [ ] `aidlc-docs/construction/plans/{unit-name}-code-generation-plan.md`에서 전체 계획 읽기
- [ ] 다음 미완료 단계 식별 (첫 번째 [ ] 체크박스)
- [ ] 해당 단계에 대한 컨텍스트 로드 (유닛, 의존성, 스토리)

## 단계 11: 현재 단계 실행
- [ ] 현재 단계가 설명하는 것을 정확히 수행
- [ ] 명시된 대로 코드, 테스트 또는 문서 생성
- [ ] 유닛의 스토리 요구사항 따르기
- [ ] 계획에 정의된 의존성 및 인터페이스 존중

## 단계 12: 진행 상황 업데이트
- [ ] 유닛 코드 생성 계획에서 완료된 단계를 [x]로 표시
- [ ] 생성이 완료되면 연관된 유닛 스토리를 [x]로 표시
- [ ] `aidlc-docs/aidlc-state.md` 현재 상태 업데이트
- [ ] 생성된 모든 산출물 저장

## 단계 13: 생성 계속 또는 완료
- [ ] 더 많은 단계가 남아 있으면 단계 10으로 돌아감
- [ ] 모든 단계가 완료되면 완료 메시지 제시로 진행

## 단계 14: 완료 메시지 제시
- 다음 구조로 완료 메시지 제시:
     1. **완료 알림** (필수): 항상 이것으로 시작:

```markdown
# 코드 생성 완료 - [unit-name]
```

     2. **AI 요약** (선택): 코드 생성의 구조화된 글머리 기호 요약 제공
        - 형식: "코드 생성이 [설명]을 생성했습니다:"
        - 생성된 주요 코드 산출물 나열 (글머리 기호)
        - 생성된 테스트 커버리지 및 문서 나열
        - 배포 산출물 및 구성 파일 언급
        - 워크플로우 지침을 포함하지 마세요 ("검토해 주세요", "알려주세요", "다음 단계로 진행", "진행하기 전에")
        - 사실적이고 내용 중심으로 유지
     3. **형식화된 워크플로우 메시지** (필수): 항상 이 정확한 형식으로 끝:

```markdown
> **검토 필요:**
> 생성된 코드를 검토해 주세요: `aidlc-docs/construction/[unit-name]/code/`



> **다음 단계**
>
> **다음 중 선택할 수 있습니다:**
>
> **변경 요청** - 검토를 기반으로 생성된 코드 수정 요청
> **다음 스테이지로 계속** - 코드 생성 승인 및 **[다음 유닛/빌드 및 테스트]**로 진행

---
```

## 단계 15: 명시적 승인 대기
- 사용자가 생성된 코드를 명시적으로 승인할 때까지 진행하지 않음
- 승인은 명확하고 모호하지 않아야 함
- 사용자가 변경을 요청하면 코드를 업데이트하고 승인 프로세스 반복

## 단계 16: 승인 기록 및 진행 상황 업데이트
- 타임스탬프와 함께 audit.md에 승인 기록
- 타임스탬프와 함께 사용자의 승인 응답 기록
- aidlc-state.md에서 이 유닛에 대한 코드 생성 스테이지를 완료로 표시

## 중요 규칙

### 계획 단계 규칙
- 모든 생성 활동에 대한 명시적이고 번호가 매겨진 단계 작성
- 계획에 스토리 추적성 포함
- 유닛 컨텍스트 및 의존성 문서화
- 생성 전 명시적 사용자 승인 받기

### 생성 단계 규칙
- **하드코딩된 로직 금지**: 유닛 계획에 작성된 것만 실행
- **계획 정확히 따르기**: 단계 순서에서 벗어나지 않음
- **체크박스 업데이트**: 각 단계 완료 직후 [x] 표시
- **스토리 추적성**: 기능이 구현되면 유닛 스토리를 [x]로 표시
- **의존성 존중**: 유닛 의존성이 충족된 경우에만 구현

## 완료 기준
- 전체 유닛 코드 생성 계획 생성 및 승인됨
- 유닛 코드 생성 계획의 모든 단계가 [x]로 표시됨
- 계획에 따라 모든 유닛 스토리 구현됨
- 모든 코드 및 테스트 생성됨 (테스트는 빌드 및 테스트 단계에서 실행)
- 배포 산출물 생성됨
- 전체 유닛이 빌드 및 검증 준비 완료
