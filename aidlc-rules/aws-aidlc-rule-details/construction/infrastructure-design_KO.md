# 인프라 설계

## 전제 조건
- 해당 유닛에 대한 기능 설계가 완료되어야 함
- NFR 설계 권장 (매핑할 논리적 컴포넌트 제공)
- 실행 계획이 인프라 설계 스테이지를 실행해야 함을 표시해야 함

## 개요
논리적 소프트웨어 컴포넌트를 배포 환경을 위한 실제 인프라 선택에 매핑합니다.

## 실행 단계

### 단계 1: 설계 산출물 분석
- `aidlc-docs/construction/{unit-name}/functional-design/`에서 기능 설계 읽기
- `aidlc-docs/construction/{unit-name}/nfr-design/`에서 NFR 설계 읽기 (있는 경우)
- 인프라가 필요한 논리적 컴포넌트 식별

### 단계 2: 인프라 설계 계획 작성
- 인프라 설계를 위한 체크박스 []가 포함된 계획 생성
- 실제 서비스에 매핑하는 데 집중 (AWS, Azure, GCP, 온프레미스)
- 각 단계에 체크박스 [] 포함

### 단계 3: 컨텍스트에 적절한 질문 생성
**지시어**: 기능 및 NFR 설계를 분석하여 이 특정 유닛의 인프라 요구에 관련된 질문만 생성합니다. 아래 카테고리를 영감으로 사용하고 필수 체크리스트로 사용하지 마세요. 해당되지 않으면 전체 카테고리를 건너뛰세요.

- [Answer]: 태그 형식을 사용하여 질문 포함
- 이 유닛에 특정한 모호함과 누락된 정보에 집중
- 인프라 결정에 사용자 입력이 필요한 경우에만 질문 생성

**예시 질문 카테고리** (필요에 따라 조정):
- **배포 환경** - 클라우드 제공자 또는 환경 설정이 불명확한 경우에만
- **컴퓨팅 인프라** - 컴퓨팅 서비스 선택에 명확화가 필요한 경우에만
- **스토리지 인프라** - 데이터베이스 또는 스토리지 선택이 모호한 경우에만
- **메시징 인프라** - 메시징/큐잉 서비스가 명세가 필요한 경우에만
- **네트워킹 인프라** - 로드 밸런싱 또는 API 게이트웨이 접근 방식이 불명확한 경우에만
- **모니터링 인프라** - 관측성 도구가 명확화가 필요한 경우에만
- **공유 인프라** - 인프라 공유 전략이 모호한 경우에만

### 단계 4: 계획 저장
- `aidlc-docs/construction/plans/{unit-name}-infrastructure-design-plan.md`로 저장
- 사용자 입력을 위한 모든 [Answer]: 태그 포함

### 단계 5: 답변 수집 및 분석
- 사용자가 모든 [Answer]: 태그를 완료할 때까지 대기
- 모호하거나 불명확한 응답 검토
- 필요시 후속 질문 추가

### 단계 6: 인프라 설계 산출물 생성
- `aidlc-docs/construction/{unit-name}/infrastructure-design/infrastructure-design.md` 생성
- `aidlc-docs/construction/{unit-name}/infrastructure-design/deployment-architecture.md` 생성
- 공유 인프라인 경우: `aidlc-docs/construction/shared-infrastructure.md` 생성

### 단계 7: 완료 메시지 제시
- 다음 구조로 완료 메시지 제시:
     1. **완료 알림** (필수): 항상 이것으로 시작:

```markdown
# 인프라 설계 완료 - [unit-name]
```

     2. **AI 요약** (선택): 인프라 설계의 구조화된 글머리 기호 요약 제공
        - 형식: "인프라 설계가 [설명]을 매핑했습니다:"
        - 주요 인프라 서비스 및 컴포넌트 나열 (글머리 기호)
        - 배포 아키텍처 결정 및 근거 나열
        - 클라우드 제공자 선택 및 서비스 매핑 언급
        - 워크플로우 지침을 포함하지 마세요 ("검토해 주세요", "알려주세요", "다음 단계로 진행", "진행하기 전에")
        - 사실적이고 내용 중심으로 유지
     3. **형식화된 워크플로우 메시지** (필수): 항상 이 정확한 형식으로 끝:

```markdown
> **검토 필요:**
> 인프라 설계를 검토해 주세요: `aidlc-docs/construction/[unit-name]/infrastructure-design/`



> **다음 단계**
>
> **다음 중 선택할 수 있습니다:**
>
> **변경 요청** - 검토를 기반으로 인프라 설계 수정 요청
> **다음 스테이지로 계속** - 인프라 설계 승인 및 **코드 생성**으로 진행

---
```

### 단계 8: 명시적 승인 대기
- 사용자가 인프라 설계를 명시적으로 승인할 때까지 진행하지 않음
- 승인은 명확하고 모호하지 않아야 함
- 사용자가 변경을 요청하면 설계를 업데이트하고 승인 프로세스 반복

### 단계 9: 승인 기록 및 진행 상황 업데이트
- 타임스탬프와 함께 audit.md에 승인 기록
- 타임스탬프와 함께 사용자의 승인 응답 기록
- aidlc-state.md에서 인프라 설계 스테이지 완료 표시
