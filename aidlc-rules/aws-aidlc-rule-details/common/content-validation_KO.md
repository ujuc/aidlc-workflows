# 콘텐츠 검증 규칙

## 필수: 파일 생성 전 콘텐츠 검증

**중요**: 모든 생성된 콘텐츠는 파싱 오류를 방지하기 위해 파일에 쓰기 전에 반드시 검증해야 합니다.

## Mermaid 다이어그램 검증

### 필수 검증 단계
1. **구문 검사**: 파일 생성 전 Mermaid 구문 검증
2. **문자 이스케이프**: 특수 문자가 적절히 이스케이프되었는지 확인
3. **대체 콘텐츠**: Mermaid 검증 실패 시 텍스트 대안 제공

### Mermaid 검증 규칙
```markdown
## Mermaid 다이어그램이 포함된 파일을 생성하기 전:

1. 노드 ID에 유효하지 않은 문자가 있는지 확인 (영숫자 + 밑줄만 사용)
2. 레이블의 특수 문자 이스케이프: " → \" 및 ' → \'
3. 플로우차트 구문 검증: 노드 연결이 유효해야 함
4. 간단한 검증으로 다이어그램 파싱 테스트

## 대체: Mermaid 검증 실패 시 텍스트 기반 워크플로우 표현 사용
```

### 구현 패턴
```markdown
## 워크플로우 시각화

### Mermaid 다이어그램 (구문이 유효한 경우)
```mermaid
[검증된 다이어그램 콘텐츠]
```

### 텍스트 대안 (항상 포함)
```
1단계: INCEPTION
- 스테이지 1: 워크스페이스 감지 (완료)
- 스테이지 2: 요구사항 분석 (완료)
[텍스트 표현 계속]
```

## 일반 콘텐츠 검증

### 생성 전 검증 체크리스트
- [ ] 임베디드 코드 블록 검증 (Mermaid, JSON, YAML)
- [ ] 특수 문자 이스케이프 확인
- [ ] 마크다운 구문 정확성 확인
- [ ] 콘텐츠 파싱 호환성 테스트
- [ ] 복잡한 요소에 대한 대체 콘텐츠 포함

### 오류 방지 규칙
1. **도구/명령을 사용하여 파일을 쓰기 전 항상 검증**: 검증되지 않은 콘텐츠를 절대 쓰지 마세요
2. **특수 문자 이스케이프**: 특히 다이어그램과 코드 블록에서
3. **대안 제공**: 시각적 콘텐츠의 텍스트 버전 포함
4. **구문 테스트**: 복잡한 콘텐츠 구조 검증

## 검증 실패 처리

### 검증 실패 시
1. **오류 기록**: 검증 실패 항목 기록
2. **대체 콘텐츠 사용**: 텍스트 기반 대안으로 전환
3. **워크플로우 계속**: 콘텐츠 검증 실패로 차단하지 마세요
4. **사용자에게 알림**: 파싱 제약으로 인해 단순화된 콘텐츠가 사용되었음을 언급
