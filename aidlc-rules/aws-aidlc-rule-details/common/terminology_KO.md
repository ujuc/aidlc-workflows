# AI-DLC 용어 사전

## 핵심 용어

### Phase(단계) vs Stage(스테이지)

**Phase(단계)**: AI-DLC의 세 가지 고수준 생명주기 단계 중 하나
- 🔵 **INCEPTION 단계** - 계획 및 아키텍처 (무엇을 그리고 왜)
- 🟢 **CONSTRUCTION 단계** - 설계, 구현 및 테스트 (어떻게)
- 🟡 **OPERATIONS 단계** - 배포 및 모니터링 (향후 확장)

**Stage(스테이지)**: 단계 내의 개별 워크플로우 활동
- 예시: 컨텍스트 평가 스테이지, 요구사항 평가 스테이지, 코드 계획 스테이지
- 각 스테이지에는 특정 전제 조건, 단계 및 출력이 있음
- 스테이지는 항상 실행 또는 조건부일 수 있음

**사용 예시**:
- ✅ "CONSTRUCTION 단계에는 7개의 스테이지가 포함됩니다"
- ✅ "코드 계획 스테이지는 항상 실행됩니다"
- ✅ "우리는 INCEPTION 단계에 있으며, 요구사항 평가 스테이지를 실행 중입니다"
- ❌ "요구사항 평가 단계" ("스테이지"여야 함)
- ❌ "CONSTRUCTION 스테이지" ("단계"여야 함)

## 3단계 생명주기

### INCEPTION 단계
**목적**: 계획 및 아키텍처 결정
**초점**: 무엇을 만들고 왜 만드는지 결정
**위치**: `inception/` 디렉토리

**스테이지**:
- 워크스페이스 감지 (항상)
- 역공학 (조건부 - 브라운필드만)
- 요구사항 분석 (항상 - 적응형 깊이)
- 사용자 스토리 (조건부)
- 워크플로우 계획 (항상)
- 애플리케이션 설계 (조건부)
- 설계 - 유닛 계획/생성 (조건부)

**출력물**: 요구사항, 사용자 스토리, 아키텍처 결정, 유닛 정의

### CONSTRUCTION 단계
**목적**: 상세 설계 및 구현
**초점**: 어떻게 만들지 결정
**위치**: `construction/` 디렉토리

**스테이지**:
- 기능 설계 (조건부, 유닛별)
- NFR 요구사항 (조건부, 유닛별)
- NFR 설계 (조건부, 유닛별)
- 인프라 설계 (조건부, 유닛별)
- 코드 계획 (항상)
- 코드 생성 (항상)
- 빌드 및 테스트 (항상)

**출력물**: 설계 산출물, NFR 구현, 코드, 테스트

### OPERATIONS 단계
**목적**: 배포 및 운영 준비
**초점**: 어떻게 배포하고 실행할지
**위치**: `operations/` 디렉토리

**스테이지**:
- Operations (플레이스홀더)

**출력물**: 빌드 지침, 배포 가이드, 모니터링 설정, 검증 절차

## 워크플로우 스테이지

### 항상 실행 스테이지
- **워크스페이스 감지**: 워크스페이스 상태 및 프로젝트 유형의 초기 분석
- **요구사항 분석**: 요구사항 수집 (깊이는 복잡성에 따라 다름)
- **워크플로우 계획**: 실행할 단계에 대한 실행 계획 생성
- **코드 계획**: 코드 생성을 위한 상세 구현 계획 생성
- **코드 생성**: 계획과 이전 산출물을 기반으로 실제 코드 생성
- **빌드 및 테스트**: 모든 유닛 빌드 및 포괄적 테스트 실행

### 조건부 스테이지
- **역공학**: 기존 코드베이스 분석 (브라운필드 프로젝트만)
- **사용자 스토리**: 사용자 스토리 및 페르소나 생성 (스토리 계획 및 스토리 생성 포함)
- **애플리케이션 설계**: 애플리케이션 컴포넌트, 메서드, 비즈니스 규칙 및 서비스 설계
- **설계**: 시스템 컴포넌트 설계 (유닛 계획, 유닛 생성, 유닛별 설계 포함)
- **기능 설계**: 기술에 구애받지 않는 비즈니스 로직 설계 (유닛별)
- **NFR 요구사항**: NFR 결정 및 기술 스택 선택 (유닛별)
- **NFR 설계**: NFR 패턴 및 논리적 컴포넌트 통합 (유닛별)
- **인프라 설계**: 실제 인프라 서비스에 매핑 (유닛별)

## 애플리케이션 설계 용어

- **컴포넌트(Component)**: 특정 책임을 가진 기능적 단위
- **메서드(Method)**: 정의된 비즈니스 규칙을 가진 컴포넌트 내의 함수 또는 작업
- **비즈니스 규칙(Business Rule)**: 메서드 동작 및 검증을 지배하는 로직
- **서비스(Service)**: 컴포넌트 간 비즈니스 로직을 조정하는 오케스트레이션 레이어
- **컴포넌트 의존성(Component Dependency)**: 컴포넌트 간의 관계 및 통신 패턴

## 아키텍처 용어 (인프라)

### 작업 단위(Unit of Work)
개발 목적으로 사용자 스토리를 논리적으로 그룹화한 것. 계획 및 분해 중에 사용되는 용어.

**사용법**: "시스템을 작업 단위로 분해해야 합니다"

### 서비스(Service)
마이크로서비스 아키텍처에서 독립적으로 배포 가능한 컴포넌트. 각 서비스는 별도의 작업 단위입니다.

**사용법**: "결제 서비스는 모든 결제 처리를 담당합니다"

### 모듈(Module)
단일 서비스 또는 모놀리스 내의 기능을 논리적으로 그룹화한 것. 모듈은 독립적으로 배포할 수 없습니다.

**사용법**: "사용자 서비스 내의 인증 모듈"

### 컴포넌트(Component)
서비스 또는 모듈 내의 재사용 가능한 구성 요소. 컴포넌트는 특정 기능을 제공하는 클래스, 함수 또는 패키지입니다.

**사용법**: "EmailValidator 컴포넌트는 이메일 주소를 검증합니다"

## 용어 가이드라인

### 각 용어를 사용해야 할 때

**작업 단위(Unit of Work)**:
- 유닛 계획 및 유닛 생성 단계 중
- 시스템 분해를 논의할 때
- 계획 문서 및 토론에서
- 예시: "이것을 작업 단위로 어떻게 분해해야 할까요?"

**서비스(Service)**:
- 독립적으로 배포 가능한 컴포넌트를 언급할 때
- 마이크로서비스 아키텍처 컨텍스트에서
- 배포 및 인프라 논의에서
- 예시: "주문 서비스는 ECS에 배포됩니다"

**모듈(Module)**:
- 서비스 내의 논리적 그룹을 언급할 때
- 모놀리스 아키텍처 컨텍스트에서
- 내부 조직을 논의할 때
- 예시: "보고 모듈은 모든 보고서를 생성합니다"

**컴포넌트(Component)**:
- 특정 클래스, 함수 또는 패키지를 언급할 때
- 설계 및 구현 논의에서
- 재사용 가능한 구성 요소를 논의할 때
- 예시: "DatabaseConnection 컴포넌트는 연결을 관리합니다"

## 스테이지 용어

### 계획(Planning) vs 생성(Generation)
- **계획(Planning)**: 실행을 위한 질문과 체크박스가 포함된 계획 생성
- **생성(Generation)**: 계획을 실행하여 산출물 생성

예시:
- 스토리 계획 → 스토리 생성
- 유닛 계획 → 유닛 생성
- 유닛 설계 계획 → 유닛 설계 생성
- NFR 계획 → NFR 생성
- 코드 계획 → 코드 생성

### 깊이 수준
- **최소(Minimal)**: 단순한 변경을 위한 빠르고 집중된 실행
- **표준(Standard)**: 일반적인 프로젝트를 위한 표준 산출물이 포함된 일반 깊이
- **포괄적(Comprehensive)**: 복잡하거나 고위험 프로젝트를 위한 모든 산출물이 포함된 전체 깊이

## 산출물 유형

### 계획(Plans)
실행을 안내하는 체크박스와 질문이 포함된 문서.
- 위치: `aidlc-docs/plans/`
- 예시: `story-generation-plan.md`, `unit-of-work-plan.md`

### 산출물(Artifacts)
계획 실행으로 생성된 출력물.
- 위치: 다양한 `aidlc-docs/` 하위 디렉토리
- 예시: `requirements.md`, `stories.md`, `design.md`

### 상태 파일(State Files)
워크플로우 진행 상황 및 상태를 추적하는 파일.
- `aidlc-state.md`: 전체 워크플로우 상태
- `audit.md`: 모든 상호작용의 완전한 감사 추적

## 일반 약어

- **AI-DLC**: AI 기반 개발 생명주기 (AI-Driven Development Life Cycle)
- **NFR**: 비기능 요구사항 (Non-Functional Requirements)
- **UOW**: 작업 단위 (Unit of Work)
- **API**: 애플리케이션 프로그래밍 인터페이스 (Application Programming Interface)
- **CDK**: 클라우드 개발 키트 (Cloud Development Kit, AWS)
