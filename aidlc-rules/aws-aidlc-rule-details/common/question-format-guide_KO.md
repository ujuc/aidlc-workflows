# 질문 형식 가이드

## 필수: 모든 질문은 이 형식을 사용해야 합니다

### 규칙: 채팅에서 질문하지 않기
**중요**: 채팅에서 직접 질문을 절대 하지 마세요. 모든 질문은 전용 질문 파일에 배치해야 합니다.

### 질문 파일 형식

#### 파일 명명 규칙
- 설명적인 이름 사용: `{phase-name}-questions.md`
- 예시:
  - `classification-questions.md`
  - `requirements-questions.md`
  - `story-planning-questions.md`
  - `design-questions.md`

#### 질문 구조
모든 질문은 의미 있는 옵션과 마지막 옵션으로 "기타"를 포함해야 합니다:

```markdown
## Question [번호]
[명확하고 구체적인 질문 텍스트]

A) [첫 번째 의미 있는 옵션]
B) [두 번째 의미 있는 옵션]
[...필요에 따라 추가 옵션...]
X) 기타 (아래 [Answer]: 태그 뒤에 설명해주세요)

[Answer]:
```

**중요**:
- "기타"는 모든 질문의 마지막 옵션으로 필수입니다
- 의미 있는 옵션만 포함하세요 - 자리를 채우기 위해 옵션을 만들지 마세요
- 적절한 만큼의 옵션을 사용하세요 (최소 2개 + 기타)

### 사용자 응답 형식
사용자는 [Answer]: 태그 뒤에 문자 선택을 채워 답변합니다:

```markdown
## Question 1
주요 사용자 인증 방법은 무엇입니까?

A) 사용자 이름과 비밀번호
B) 소셜 미디어 로그인 (Google, Facebook)
C) 싱글 사인온 (SSO)
D) 다단계 인증

[Answer]: C
```

### 사용자 응답 읽기
사용자가 완료를 확인한 후:
1. 질문 파일 읽기
2. [Answer]: 태그 뒤의 답변 추출
3. 모든 질문이 답변되었는지 검증
4. 응답을 기반으로 분석 진행

### 객관식 가이드라인

#### 옵션 수
- 최소: 2개의 의미 있는 옵션 + "기타" (A, B, C)
- 일반: 3-4개의 의미 있는 옵션 + "기타" (A, B, C, D, E)
- 최대: 5개의 의미 있는 옵션 + "기타" (A, B, C, D, E, F)
- **중요**: 자리를 채우기 위해 옵션을 만들지 마세요 - 의미 있는 선택만 포함

#### 옵션 품질
- 옵션을 상호 배타적으로 만들기
- 가장 일반적인 시나리오 포함
- 의미 있고 현실적인 옵션만 포함
- **항상 "기타"를 마지막 옵션으로 포함** (필수)
- 구체적이고 명확하게
- **A, B, C, D 자리를 채우기 위해 옵션을 만들지 마세요**

#### 좋은 예시:
```markdown
## Question 5
어떤 데이터베이스 기술을 사용할 예정입니까?

C) NoSQL 키-값 (Redis, Memcached)
D) 그래프 데이터베이스 (Neo4j, Neptune)
E) 기타 (아래 [Answer]: 태그 뒤에 설명해주세요)

[Answer]:
```

#### 나쁜 예시 (피하세요):
```markdown

```

### 워크플로우 통합

#### 단계 1: 질문 파일 생성
```markdown
모든 질문이 포함된 aidlc-docs/{phase-name}-questions.md 생성
```

#### 단계 2: 사용자에게 알림
```
"[X]개의 질문이 포함된 {phase-name}-questions.md를 생성했습니다.
[Answer]: 태그 뒤에 문자 선택을 채워 각 질문에 답변해 주세요.
옵션 중 귀하의 요구에 맞는 것이 없으면 마지막 옵션(기타)을 선택하고 선호 사항을 설명해 주세요. 완료되면 알려주세요."
```

#### 단계 3: 확인 대기
사용자가 "완료", "끝", "다 했습니다" 또는 유사한 말을 할 때까지 대기.

#### 단계 4: 읽기 및 분석
```
aidlc-docs/{phase-name}-questions.md 읽기
모든 답변 추출
완전성 검증
분석 진행
```

### 오류 처리

#### 누락된 답변
[Answer]: 태그가 비어 있는 경우:
```
"Question [X]가 답변되지 않았습니다. 진행하기 전에
모든 질문에 대해 문자 선택 중 하나를 사용하여 답변해 주세요."
```

#### 유효하지 않은 답변
답변이 유효한 문자 선택이 아닌 경우:
```
"Question [X]에 유효하지 않은 답변 '[answer]'가 있습니다.
질문에 제공된 문자 선택만 사용해 주세요."
```

#### 모호한 답변
사용자가 문자 대신 설명을 제공한 경우:
```
"Question [X]에 대해 답변에 가장 잘 맞는 문자 선택을 제공해 주세요.
일치하는 것이 없으면 '기타'를 선택하고 [Answer]: 태그 뒤에 설명을 추가해 주세요."
```

### 모순 및 모호성 감지

**필수**: 사용자 응답을 읽은 후 모순과 모호성을 반드시 확인해야 합니다.

#### 모순 감지
논리적으로 일관성이 없는 답변 찾기:
- 범위 불일치: "버그 수정"이지만 "전체 코드베이스에 영향"
- 리스크 불일치: "낮은 리스크"이지만 "브레이킹 체인지"
- 일정 불일치: "빠른 수정"이지만 "여러 하위 시스템"
- 영향 불일치: "단일 컴포넌트"이지만 "상당한 아키텍처 변경"

#### 모호성 감지
불명확하거나 경계선에 있는 응답 찾기:
- 여러 분류에 맞을 수 있는 답변
- 구체성이 부족한 응답
- 여러 질문에 걸쳐 충돌하는 지표

#### 명확화 질문 생성
모순이나 모호성이 감지된 경우:

1. **명확화 파일 생성**: `{phase-name}-clarification-questions.md`
2. **문제 설명**: 어떤 모순/모호성이 감지되었는지 명확히 설명
3. **타겟팅된 질문**: 문제를 해결하기 위해 객관식 형식 사용
4. **원래 질문 참조**: 어떤 질문이 충돌하는 답변을 가졌는지 표시

**예시**:
```markdown
# [단계 이름] 명확화 질문

응답에서 명확화가 필요한 모순을 감지했습니다:

## 모순 1: [간략한 설명]
"[답변 A]" (Q[X]:[문자])를 표시했지만 "[답변 B]" (Q[Y]:[문자])도 표시했습니다.
이러한 응답은 [설명] 때문에 모순됩니다.

### 명확화 질문 1
[모순을 해결하기 위한 구체적인 질문]

A) [첫 번째 답변 방향으로 해결하는 옵션]
B) [두 번째 답변 방향으로 해결하는 옵션]
C) [중간 지점을 제공하는 옵션]
D) [질문을 재구성하는 옵션]

[Answer]:

## 모호성 1: [간략한 설명]
Q[X]에 대한 응답 ("[답변]")은 [설명] 때문에 모호합니다.

### 명확화 질문 2
[모호성을 명확히 하기 위한 구체적인 질문]

A) [명확한 옵션 1]
B) [명확한 옵션 2]
C) [명확한 옵션 3]
D) [명확한 옵션 4]

[Answer]:
```

#### 명확화 워크플로우

1. **감지**: 모든 응답을 모순/모호성에 대해 분석
2. **생성**: 문제가 발견되면 명확화 질문 파일 생성
3. **알림**: 사용자에게 문제와 명확화 파일에 대해 알림
4. **대기**: 사용자가 명확화를 제공할 때까지 진행하지 않음
5. **재검증**: 명확화 후 일관성을 다시 확인
6. **진행**: 모든 모순이 해결된 경우에만 진행

#### 예시 사용자 메시지
```
"응답에서 2개의 모순을 감지했습니다:

1. 버그 수정 범위 vs. 코드베이스 영향 (Q1 vs Q2)
2. 낮은 리스크 vs. 브레이킹 체인지 (Q7 vs Q4)

이를 해결하기 위해 2개의 질문이 포함된 classification-clarification-questions.md를 생성했습니다.
분류를 진행하기 전에 이러한 명확화 질문에 답변해 주세요."
```

### 모범 사례

1. **구체적으로**: 질문은 명확하고 모호하지 않아야 함
2. **포괄적으로**: 필요한 모든 정보를 포함
3. **간결하게**: 질문을 하나의 주제에 집중
4. **실용적으로**: 옵션은 현실적이고 실행 가능해야 함
5. **일관되게**: 모든 질문 파일에서 동일한 형식 사용

## 요약

**기억하세요**:
- ✅ 항상 질문 파일 생성
- ✅ 항상 객관식 형식 사용
- ✅ **항상 "기타"를 마지막 옵션으로 포함 (필수)**
- ✅ 의미 있는 옵션만 포함 - 자리를 채우기 위해 옵션을 만들지 마세요
- ✅ 항상 [Answer]: 태그 사용
- ✅ 항상 사용자 완료 대기
- ✅ 항상 모순에 대해 응답 검증
- ✅ 필요시 항상 명확화 파일 생성
