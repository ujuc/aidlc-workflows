# 과신 방지 가이드

## 문제 정의

AI-DLC가 복잡한 프로젝트 의도 진술에 대해서도 충분한 명확화 질문을 하지 않고 과신을 보이고 있었습니다. 이로 인해 적절한 요구사항을 수집하는 대신 가정을 하게 되었습니다.

## 근본 원인 분석

과신 문제는 여러 스테이지에서 질문 건너뛰기를 장려하는 지시어들로 인해 발생했습니다:

1. **기능 설계**: "해당되지 않는 경우 전체 카테고리 건너뛰기"
2. **사용자 스토리**: "카테고리를 영감으로 사용하고, 필수 체크리스트로 사용하지 않음"
3. **요구사항 분석**: 최소한의 질문을 장려하는 유사한 패턴
4. **NFR 요구사항**: 철저한 분석을 저해하는 "~인 경우에만" 조건들

이러한 지시어들은 AI에게 포괄적인 요구사항 수집을 장려하기보다 질문을 피하라고 말하고 있었습니다.

## 구현된 솔루션

### 업데이트된 질문 생성 철학

**이전 접근 방식**: "절대적으로 필요한 경우에만 질문하기"
**새로운 접근 방식**: "의심스러우면 질문하기 - 과신은 나쁜 결과로 이어짐"

### 주요 변경 사항

#### 1. 요구사항 분석 스테이지
- "필요한 경우에만"에서 "예외적으로 명확한 경우가 아니면 항상 질문 생성"으로 변경
- 포괄적인 평가 영역 추가 (기능적, 비기능적, 비즈니스 컨텍스트, 기술적 컨텍스트)
- 선제적 질문 접근 방식 강조

#### 2. 사용자 스토리 스테이지
- "전체 카테고리 건너뛰기" 지시어 제거
- 평가할 포괄적인 질문 카테고리 추가
- 답변 분석 요구사항 강화
- 후속 질문 의무 강화

#### 3. 기능 설계 스테이지
- "~인 경우에만" 조건을 포괄적 평가로 대체
- 더 많은 질문 카테고리 추가 (데이터 흐름, 통합 지점, 오류 처리)
- 모호성 감지 및 해결 요구사항 강화

#### 4. NFR 요구사항 스테이지
- 기본 NFR을 넘어 질문 카테고리 확장
- 신뢰성, 유지보수성, 사용성 고려사항 추가
- 기술적 모호성에 대한 답변 분석 강화

### 새로운 지침 원칙

1. **기본적으로 질문하기**: 모호함이 있으면 명확화 질문하기
2. **포괄적 범위**: 모든 관련 카테고리 평가, 영역 건너뛰지 않기
3. **철저한 분석**: 모호함에 대해 모든 사용자 응답을 신중하게 분석
4. **필수 후속 질문**: 불명확한 응답에 대해 후속 질문 생성
5. **모호함과 함께 진행 금지**: 모든 모호함이 해결될 때까지 진행하지 않기

## 구현 가이드라인

### 질문 생성을 위해
- 모든 질문 카테고리 평가, 건너뛰지 않기
- 명확화가 품질을 향상시킬 수 있는 곳에 질문하기
- 각 스테이지에 포괄적인 질문 카테고리 포함
- 질문의 제외보다 포함을 기본으로

### 답변 분석을 위해
- 모호한 응답 찾기: "상황에 따라", "아마도", "잘 모르겠음", "혼합", "그 사이 어딘가"
- 정의되지 않은 용어와 외부 개념에 대한 참조 감지
- 모순되거나 불완전한 답변 식별
- 모든 모호함에 대해 후속 질문 생성

### 후속 질문을 위해
- 모호함이 감지되면 별도의 명확화 파일 생성
- 각 모호함을 해결하기 위한 구체적인 질문하기
- 모든 불명확한 응답이 명확해질 때까지 진행하지 않기
- 철저하게 - 과소 명확화보다 과다 명확화가 나음

## 품질 보증

### 주의해야 할 위험 신호
- 복잡한 프로젝트에서 질문 없이 스테이지 완료
- 모호하거나 불명확한 사용자 응답으로 진행
- 정당화 없이 전체 질문 카테고리 건너뛰기
- 명확화 요청 대신 가정하기

### 성공 지표
- 프로젝트 복잡성에 적절한 수의 명확화 질문
- 필요시 후속 질문과 함께 사용자 응답의 철저한 분석
- 구현으로 진행하기 전 명확하고 모호하지 않은 요구사항
- 더 나은 사전 명확화로 인해 후반 스테이지에서 변경 필요성 감소

## 유지보수

이 가이드는 다음 경우에 참조해야 합니다:
- AI-DLC에 새 스테이지 추가 시
- 기존 스테이지 지침 업데이트 시
- 과신 문제에 대해 AI-DLC 성능 검토 시
- AI-DLC 질문 생성 원칙에 대해 팀원 교육 시

## 핵심 요점

**잘못된 가정을 하는 것보다 너무 많은 질문을 하는 것이 낫습니다.** 사전에 명확화 질문을 하는 비용은 가정을 기반으로 잘못된 솔루션을 구현하는 비용보다 훨씬 적습니다.
