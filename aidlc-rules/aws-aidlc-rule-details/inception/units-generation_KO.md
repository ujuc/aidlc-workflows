# 유닛 생성 - 상세 단계

## 개요
이 스테이지는 두 가지 통합 파트를 통해 시스템을 관리 가능한 작업 단위로 분해합니다:
- **파트 1 - 계획**: 질문이 포함된 분해 계획 생성, 답변 수집, 모호함 분석, 승인 받기
- **파트 2 - 생성**: 승인된 계획을 실행하여 유닛 산출물 생성

**정의**: 작업 단위는 개발 목적을 위한 스토리의 논리적 그룹핑입니다. 마이크로서비스의 경우 각 유닛은 독립적으로 배포 가능한 서비스가 됩니다. 모놀리스의 경우 단일 유닛이 논리적 모듈이 있는 전체 애플리케이션을 나타냅니다.

**용어**: 독립적으로 배포 가능한 컴포넌트에는 "서비스", 서비스 내 논리적 그룹핑에는 "모듈", 계획 컨텍스트에는 "작업 단위" 사용.

## 전제 조건
- 컨텍스트 평가가 완료되어야 함
- 요구사항 평가 권장 (기능 범위 제공)
- 스토리 개발 권장 (스토리가 유닛에 매핑됨)
- 애플리케이션 설계 단계 필수 (컴포넌트, 메서드, 서비스 결정)
- 실행 계획이 설계 단계를 실행해야 함을 표시해야 함

# 파트 1: 계획

## 단계 1: 작업 단위 계획 생성
- 시스템을 작업 단위로 분해하기 위한 체크박스 []가 포함된 계획 생성
- 시스템을 관리 가능한 개발 단위로 분해하는 데 집중
- 각 단계 및 하위 단계에 체크박스 [] 포함

## 단계 2: 계획에 필수 유닛 산출물 포함
**항상** 이러한 필수 산출물을 유닛 계획에 포함:
- [ ] 유닛 정의 및 책임이 포함된 `aidlc-docs/inception/application-design/unit-of-work.md` 생성
- [ ] 의존성 매트릭스가 포함된 `aidlc-docs/inception/application-design/unit-of-work-dependency.md` 생성
- [ ] 스토리를 유닛에 매핑하는 `aidlc-docs/inception/application-design/unit-of-work-story-map.md` 생성
- [ ] 유닛 경계 및 의존성 검증
- [ ] 모든 스토리가 유닛에 할당되었는지 확인

## 단계 3: 컨텍스트에 적절한 질문 생성
**지시어**: 요구사항, 스토리, 애플리케이션 설계를 분석하여 이 특정 분해 문제에 관련된 질문만 생성합니다. 아래 카테고리를 영감으로 사용하고 필수 체크리스트로 사용하지 마세요. 해당되지 않으면 전체 카테고리를 건너뛰세요.

- [Answer]: 태그 형식을 사용하여 질문 포함
- 이 컨텍스트에 특정한 모호함과 누락된 정보에 집중
- 의사 결정에 사용자 입력이 필요한 경우에만 질문 생성

**예시 질문 카테고리** (필요에 따라 조정):
- **스토리 그룹핑** - 여러 스토리가 존재하고 그룹핑 전략이 불명확한 경우에만
- **의존성** - 여러 유닛이 있을 가능성이 있고 통합 접근 방식이 모호한 경우에만
- **팀 정렬** - 팀 구조나 소유권이 불명확한 경우에만
- **기술 고려사항** - 유닛 간 확장성/배포 요구사항이 다른 경우에만
- **비즈니스 도메인** - 도메인 경계 또는 바운디드 컨텍스트가 불명확한 경우에만

## 단계 4: UOW 계획 저장
- `aidlc-docs/inception/plans/unit-of-work-plan.md`로 저장
- 사용자 입력을 위한 모든 [Answer]: 태그 포함
- 계획이 시스템 분해의 모든 측면을 다루는지 확인

## 단계 5: 사용자 입력 요청
- 사용자가 계획 문서에서 직접 [Answer]: 태그를 채우도록 요청
- 분해 결정의 중요성 강조
- [Answer]: 태그 완료에 대한 명확한 지침 제공

## 단계 6: 답변 수집
- 사용자가 문서에서 [Answer]: 태그를 사용하여 모든 질문에 답변할 때까지 대기
- 모든 [Answer]: 태그가 완료될 때까지 진행하지 않음
- 문서를 검토하여 빈 [Answer]: 태그가 없는지 확인

## 단계 7: 답변 분석 (필수)
진행하기 전에 모든 사용자 답변을 다음에 대해 신중하게 검토해야 함:
- **모호하거나 애매한 응답**: "혼합", "그 사이 어딘가", "잘 모르겠음", "상황에 따라"
- **정의되지 않은 기준 또는 용어**: 명확한 정의 없는 개념 참조
- **모순된 답변**: 서로 충돌하는 응답
- **누락된 생성 세부사항**: 구체적인 안내가 부족한 답변
- **옵션을 결합한 답변**: 명확한 결정 규칙 없이 다른 접근 방식을 병합한 응답

## 단계 8: 필수 후속 질문
7단계의 분석에서 모호한 답변이 발견되면 반드시:
- [Answer]: 태그를 사용하여 계획 문서에 구체적인 후속 질문 추가
- 모든 모호함이 해결될 때까지 승인으로 진행하지 않음
- 필요한 후속 질문 예시:
  - "'A와 B의 혼합'이라고 하셨는데 - A와 B를 언제 사용할지 결정하는 구체적인 기준은 무엇인가요?"
  - "'A와 B 사이 어딘가'라고 하셨는데 - 정확한 중간 접근 방식을 정의해 주실 수 있나요?"
  - "'잘 모르겠음'이라고 하셨는데 - 결정에 도움이 될 추가 정보는 무엇인가요?"
  - "'복잡성에 따라'라고 하셨는데 - 복잡성 수준을 어떻게 정의하시나요?"

## 단계 9: 승인 요청
- 질문: "**작업 단위 계획 완료. aidlc-docs/inception/plans/unit-of-work-plan.md에서 계획을 검토하세요. 생성으로 진행할 준비가 되셨나요?**"
- 사용자가 확인할 때까지 진행하지 않음

## 단계 10: 승인 기록
- 타임스탬프와 함께 audit.md에 프롬프트 및 응답 기록
- ISO 8601 타임스탬프 형식 사용
- 완전한 승인 프롬프트 텍스트 포함

## 단계 11: 진행 상황 업데이트
- aidlc-state.md에서 유닛 계획 완료 표시
- "현재 상태" 섹션 업데이트
- 유닛 생성으로 전환 준비

# 파트 2: 생성

## 단계 12: 작업 단위 계획 로드
- [ ] `aidlc-docs/inception/plans/unit-of-work-plan.md`에서 완전한 계획 읽기
- [ ] 다음 미완료 단계 식별 (첫 번째 [ ] 체크박스)
- [ ] 해당 단계에 대한 컨텍스트 및 요구사항 로드

## 단계 13: 현재 단계 실행
- [ ] 현재 단계가 설명하는 것을 정확히 수행
- [ ] 계획에 지정된 대로 유닛 산출물 생성
- [ ] 계획에서 승인된 분해 접근 방식 따르기
- [ ] 계획에 지정된 기준 및 경계 사용

## 단계 14: 진행 상황 업데이트
- [ ] 작업 단위 계획에서 완료된 단계를 [x]로 표시
- [ ] `aidlc-docs/aidlc-state.md` 현재 상태 업데이트
- [ ] 생성된 모든 산출물 저장

## 단계 15: 계속 또는 완료
- [ ] 더 많은 단계가 남아 있으면 12단계로 돌아감
- [ ] 모든 단계가 완료되면 유닛이 설계 스테이지를 위해 준비되었는지 확인
- [ ] 유닛 생성 스테이지를 완료로 표시

## 단계 16: 완료 메시지 제시

```markdown
# 🔧 유닛 생성 완료

[AI가 생성한 유닛 및 분해 요약 (글머리 기호 형식)]

> **📋 <u>**검토 필요:**</u>**
> 유닛 생성 산출물을 검토해 주세요: `aidlc-docs/inception/application-design/`

> **🚀 <u>**다음 단계?**</u>**
>
> **다음 중 선택할 수 있습니다:**
>
> 🔧 **변경 요청** - 필요시 유닛 생성 수정 요청
> ✅ **승인 및 계속** - 유닛 승인 및 **CONSTRUCTION 단계**로 진행
```

## 단계 17: 명시적 승인 대기
- 사용자가 유닛 생성을 명시적으로 승인할 때까지 진행하지 않음
- 승인은 명확하고 모호하지 않아야 함
- 사용자가 변경을 요청하면 유닛을 업데이트하고 승인 프로세스 반복

## 단계 18: 승인 응답 기록
- 타임스탬프와 함께 `aidlc-docs/audit.md`에 사용자의 승인 응답 기록
- 정확한 사용자 응답 텍스트 포함
- 승인 상태를 명확히 표시

## 단계 19: 진행 상황 업데이트
- `aidlc-docs/aidlc-state.md`에서 유닛 생성 스테이지 완료 표시
- "현재 상태" 섹션 업데이트
- CONSTRUCTION 단계로 전환 준비

## 중요 규칙

### 계획 단계 규칙
- 컨텍스트에 관련된 질문만 생성
- 모든 질문에 [Answer]: 태그 형식 사용
- 진행 전 모든 답변에서 모호함 분석
- 후속 질문으로 모든 모호함 해결
- 생성 전 명시적 사용자 승인 받기

### 생성 단계 규칙
- **하드코딩된 로직 금지**: 작업 단위 계획에 작성된 것만 실행
- **계획 정확히 따르기**: 단계 순서에서 벗어나지 않음
- **체크박스 업데이트**: 각 단계 완료 직후 [x] 표시
- **승인된 접근 방식 사용**: 계획의 분해 방법론 따르기
- **완료 확인**: 진행 전 모든 유닛 산출물이 완료되었는지 확인

## 완료 기준
- 모든 계획 질문에 답변되고 모호함 해결됨
- 계획에 대한 사용자 승인 획득
- 작업 단위 계획의 모든 단계가 [x]로 표시됨
- 계획에 따라 모든 유닛 산출물 생성됨:
  - 유닛 정의가 포함된 `unit-of-work.md`
  - 의존성 매트릭스가 포함된 `unit-of-work-dependency.md`
  - 스토리 매핑이 포함된 `unit-of-work-story-map.md`
- 유닛이 검증되고 유닛별 설계 스테이지를 위해 준비됨
