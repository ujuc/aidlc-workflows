# 리버스 엔지니어링

**목적**: 기존 코드베이스를 분석하고 포괄적인 설계 산출물 생성

**실행 시점**: 브라운필드 프로젝트 감지 시 (워크스페이스에 기존 코드가 있는 경우)

**건너뛰기 시점**: 그린필드 프로젝트 (기존 코드 없음)

**재실행 동작**: 브라운필드 프로젝트가 감지되면 산출물이 존재하더라도 항상 재실행. 이는 산출물이 현재 코드 상태를 반영하도록 보장

## 단계 1: 멀티 패키지 탐색

### 1.1 워크스페이스 스캔
- 모든 패키지 (언급된 것뿐만 아니라)
- 구성 파일을 통한 패키지 관계
- 패키지 유형: 애플리케이션, CDK/인프라, 모델, 클라이언트, 테스트

### 1.2 비즈니스 컨텍스트 이해
- 시스템이 전체적으로 구현하는 핵심 비즈니스
- 모든 패키지의 비즈니스 개요
- 시스템에 구현된 비즈니스 트랜잭션 목록

### 1.3 인프라 탐색
- CDK 패키지 (CDK 의존성이 있는 package.json)
- Terraform (.tf 파일)
- CloudFormation (.yaml/.json 템플릿)
- 배포 스크립트

### 1.4 빌드 시스템 탐색
- 빌드 시스템: Brazil, Maven, Gradle, npm
- 빌드 시스템 선언을 위한 구성 파일
- 패키지 간 빌드 의존성

### 1.5 서비스 아키텍처 탐색
- Lambda 함수 (핸들러, 트리거)
- 컨테이너 서비스 (Docker/ECS 구성)
- API 정의 (Smithy 모델, OpenAPI 스펙)
- 데이터 저장소 (DynamoDB, S3 등)

### 1.6 코드 품질 분석
- 프로그래밍 언어 및 프레임워크
- 테스트 커버리지 지표
- 린팅 구성
- CI/CD 파이프라인
